# PDF 对象级配色

正文、链接预览和放大预览使用同一套 `pdfObjectColors` 配色。范围是文字型 PDF；不实现扫描件背景分割或 OCR 重绘。位图图片保留原色，旧的图片反色、自适应白底处理设置不再参与渲染，设置页也不再提供这些选项。原有偏好字段暂时保留，兼容已有配置。

## 绘制路径

`pdf-dark-mode.ts` 提供石墨和纯黑配色，以及按原始绘制颜色缓存的 `mapColor`。`patches/pdfjs-dist@6.3.289.patch` 扩展 PDF.js 的 `pageColors`，在执行绘制指令前将文字、实色填充和描边的颜色映射到画布。PDF 图形状态保留原始颜色，保存/恢复状态不会重复改色。字体边缘由绘制器直接在目标颜色之间生成；不读取整页像素，也不使用整页高对比度滤镜。

普通 RGB 图片、渐变和图案保留原色。模板图像（stencil）是用当前墨色绘制的单色形状，缓存键及填充使用映射后的颜色。透明遮罩中的亮度值是透明度数据，必须保持原值。Type3 字体的嵌套绘制指令经过相同映射。

这不是 PDF 语义版面识别：白色实色路径按纸张色映射，无论它原本代表页面背景还是图表内的白色区域；复杂渐变、彩色图案不会自动适配深色背景。不会修改 PDF 原文件、导出文件或文本层，也不改变文字选择与定位。

## 显示和重绘

PDF.js 将新画面绘制完成后才替换旧画布。深色渲染取消或失败时保留上一张完整画布；不再存在“旧画布已移除，新画布还在等待像素 Worker”的空档。正文、局部高清画布与文字/批注层继续使用原有层级。

`focusBlock` 的 240ms 动画使用延迟绘制，结束时刷新一次并清除延迟计时器。缩放值按 PDF.js 的百分之一精度合并，相同倍率不重复提交。缩放期间不更新局部高清区域；原有 PDF.js 调度器同时推迟局部高清渲染。中断动画后仍有延迟计时器负责最终清晰重绘。

主题变化使用 `PDFPageView.update({ pageColors })`，保留旧画布；重复应用同一配色或收到解析 blocks 都不重绘 PDF。

## 补丁维护和验证

补丁仅修改 `build/pdf.mjs`、`legacy/build/pdf.mjs` 和 `web/pdf_viewer.mjs`。生产前端与 Node 离屏测试使用相同绘制逻辑；处理器不传入 `mapColor`，保持原渲染行为。升级 PDF.js 时必须重新检查软遮罩、模板图像、画布取消回调、局部高清刷新和 `pageColors` 传递路径。

`pdf-object-rendering.test.ts` 使用真实 PDF.js 和原生画布，比较对象改色结果与直接以目标颜色制作的参考 PDF。覆盖两种配色、三个倍率、文字、细线、透明图形、位图、亮度遮罩和模板图像。`pdf-canvas-lifecycle.test.ts` 执行已安装 PDF.js 的实际内部类，验证完成后替换、取消及失败保留旧画布。导航测试验证动画中不立即刷新、结束仅刷新一次、相同倍率不重绘。

首次页面或局部渲染失败记录 `pdf.render.failed`，只记录绘制路径及图层类型，不保存文档内容、路径或原始异常。每个阅读实例最多记录一次，避免失败循环刷日志。

自动测试不能替代桌面视觉验收。人工检查：石墨/纯黑之间切换；连续滚轮缩放和触控板缩放；放大后点击不同 block 及重复点击同一 block；在动画中滚动/点击中断；确认无空白闪烁、双重字形、文字选择遮挡，图片保持原色。运动中的位图仍可能暂时拉伸，最终清晰度以停止缩放后的高清结果为准。
